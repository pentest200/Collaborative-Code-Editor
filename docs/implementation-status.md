## Durability scope, carried-forward gaps and next gate

Only server-acknowledged updates are covered by the verified worker-restart guarantee. PostgreSQL may finish an in-flight statement after a client process dies; the before-commit crash test keeps its insert blocked until the database statement timeout aborts, rather than assuming process death proves rollback. The post-commit test kills before broadcast/ACK and later replays the original identity for its original sequence. Snapshot death and renewal death use test-only subprocess IPC barriers; production exposes no fault-injection endpoint.

The browser has no retained outbox or automatic reconnect yet. A 15-second dead-owner lease delays room admission; users currently reload after expiry. Old-generation rejections do not yet retain/export a recoverable browser draft. Corrupt snapshots fail closed and require operator repair. Payload quota excludes snapshot/table/index overhead; retained logs require storage monitoring/backups. Live OAuth and sustained load/resource/failure measurement remain unverified, as carried forward from Phase 03. Linux race verification is passed, not blocked.

Phase 04 implementation and its required verification are complete, with the limitations above recorded. There is no remaining Phase 04 blocker. The next phase is ready: Phase 05 — drafts, reconnect, presence, and selective undo. It was not started in this turn.
