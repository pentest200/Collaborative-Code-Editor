# Current limitations

Phase 04 commits identified edit bytes and contiguous sequences to PostgreSQL before broadcasting or acknowledging. Verified snapshot/log replay recovers server-acknowledged edits after collaboration worker death. This is the durability scope tested; it does not establish recovery from host/disk loss or provide backups. Logs are retained. The project quota counts update payloads (default 1 GiB), rather than total database/index/snapshot disk usage. An independent 10 MiB active-source quota uses committed UTF-8 size projections; deleted and replaced generations release that source budget while their update logs remain retained.

Browser receipt tracking is in memory. No IndexedDB draft/outbox, automatic reconnect/retry, draft export, authenticated awareness/cursors or selective local undo exists yet. Unacknowledged work can be lost on browser reload/tab close, including after a storage failure. The UI says Saving until matching receipts arrive and exposes storage/access failures. A committed-state sync yields Synced, not Saved. The editor stops accepting typing on transport/storage/access errors. Phase 05 is required before valuable offline editing or crash-safe local retention can be promised.

Yjs decode, replay, candidate validation and encoding run in worker threads with bounded heap/time/concurrency; pending structs are checked as well as visible text. Rooms/queues/hydration are bounded. The recorded candidate timings are individual samples, not load capacity or latency percentiles. Heap samples are not whole-process RSS or proof of hostile-load capacity. Slow-client ceilings, sustained malformed traffic, long database/Redis outages, quota-scale replay and resource fairness remain unmeasured release gates for Phase 09. Snapshot corruption fails closed and currently needs operator repair; there is no administrative recovery UI or log pruning.

One worker is statically routed. On abrupt death its 15-second DB lease must expire before takeover; browser users reload to reconnect. A stale fence cannot append. Multi-worker routing, rebalance and horizontal capacity are Phase 10 work. Redis remains configured but is not on the append/receipt/event durability path.

Checkpoints/restore UI, execution, search, metrics/traces and the release demonstration are unfinished Phases 06–09. Old-generation rejection is tested by database pointer replacement; this does not implement checkpoint restoration or local old-draft recovery. Output remains explicitly unavailable.

The browser tests use separate seeded owner/editor sessions and a viewer session, not live GitHub OAuth. The earlier two editing contexts shared one owner identity; Phase 04 now verifies distinct editing accounts. GitHub login remains fixture-tested; no live credentials were supplied. Local Compose credentials and HTTP are development-only. The Windows C compiler still cannot build Go race tests; Go race verification passes in Linux, including the current phase. No production-readiness or scaling claim is made.
