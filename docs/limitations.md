# Current limitations

Phase 02 supports GitHub.com sign-in, private project/team access, file/folder organization, and a read-only Monaco workspace. Users cannot edit file contents, collaborate, save code, run code, restore checkpoints or search yet. The workspace labels editing and Output as unavailable. Login requires a configured GitHub OAuth App; only fixture provider login was tested because no live credentials were supplied. An invited user who signs in from an invitation must reopen the invitation link after login.

The Phase 02 migration adds deferred active-tree checks for parent kind/state, current file generation, cycles, depth and path size. The API checks names and version preconditions, serializes metadata mutations with project row locks, and enforces a 200-active-entry cap. File creation persists an encoded empty Yjs snapshot from the private TypeScript initializer. No service accepts or saves browser edits yet. Document append policy, source-byte quota enforcement, scoped worker functions, and job leasing remain later-phase work.

Compose uses development-only database credentials and localhost HTTP. It is not a deployment setup. MinIO, runner, metrics and scaling services are intentionally absent until later phases. No performance, collaboration durability, failover or production capacity claim follows from this phase.

The PostgreSQL test container applied all three migrations and ran real API integration tests. Phase 02's Compose retry built and started the full stack after correcting a Caddyfile syntax error; same-origin HTTP smoke passed. The TypeScript and Go framing tests cover the envelope and one durable ACK fixture; complete frame-body codecs are Phase 03 work. The optional Go race build still cannot compile with the installed 32-bit Windows C compiler. Phase 02 browser checks used mocked API responses; no authenticated end-to-end browser flow against Compose or live GitHub account was tested.
