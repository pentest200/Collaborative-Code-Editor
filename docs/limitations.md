# Current limitations

Phase 04 commits identified update bytes and contiguous sequences before broadcast/ACK. Snapshot/log replay recovers server-acknowledged edits after worker death; this does not establish recovery from disk/host loss or replace backups. Logs remain retained, with a 1 GiB update-payload quota excluding table/index/snapshot overhead. Active project source has an independent 10 MiB committed UTF-8 size quota; deleted/replaced generations release active-source budget.

Phase 05 retains account/project/file/document-generation-scoped Yjs state and original receipt identities in IndexedDB before sending. Offline typing is available after initialization; browser reload recovers retained state/outbox when the web application and authenticated metadata can load. It is not an offline-installed application: reloading the entire site with all HTTP access unavailable cannot load the workspace. Edits still awaiting local transaction completion, browser eviction, cleared site data and device/profile loss have no crash-proof retention promise. Limits are 2 MiB encoded retained state, 8 MiB outbox and 4096 entries per account/generation. Storage failure/full stops typing/sending and offers the visible draft download; state beyond the failed transaction exists only in the open tab.

Reconnect is automatic with fresh authorization, committed-state sync and original-identity replay. A dead worker's 15-second lease and jittered retry backoff delay recovery. Revoked/expired access and invalidated generations stop replay and retain separate exportable drafts. Explicit logout removes account caches and clears/closes other tab providers; expired sessions retain drafts for later recovery. Caches are not encrypted. Failed logout cleanup is surfaced; use separate browser profiles on shared devices. Selective undo history belongs to the active binding and resets on switch/reload. There is one active provider/model and no inactive model cache.

Cursors use relative positions and authenticated server identity, with connection-bound awareness IDs, payload/clock/rate bounds, timeout and disconnect cleanup. Presence is lossy; it has no receipt or durability guarantee. Redis is configured but is not required for document/event/presence correctness in this single-worker topology. Two-second reader revalidation remains a bounded revocation guarantee; source already delivered cannot be erased by revocation.

Yjs candidate/replay/encoding work is isolated and bounded. Recorded Phase 04 timings are individual samples, not latency percentiles, whole-process RSS or throughput. Sustained hostile traffic, slow-client ceilings, long database/Redis outages, quota-scale hydration, resource fairness and capacity remain Phase 09 measurement gates. Snapshot corruption fails closed and requires operator repair. No administrative repair UI or log pruning exists. One worker is statically routed; horizontal routing/rebalance is Phase 10.

Phase 06 implements checkpoint capture/materialization/preview/restore and actual restore/offline-draft acceptance. Previous state is durably captured in the replacement transaction, but its preview depends on successful independent materialization. Failed uploads remain private/incomplete and need owner/editor retry; abandoned claims wait up to five minutes for takeover. Checkpoint inputs/logs/artifacts are retained without pruning or an administrative repair UI. Lists show the latest 100 checkpoints. Long storage outages, storage-volume loss/backup recovery and quota-scale materialization remain unmeasured. MinIO uses pinned upstream source because former official image pulls were rejected. Metrics/traces and measured release remain unfinished Phase 09.

Live GitHub OAuth remains unverified because credentials were not supplied. OAuth fixtures and independently seeded owner/editor/viewer sessions test auth behavior without live provider credentials. Local HTTP/Compose credentials are development-only. The Windows compiler still cannot build Go race tests; Linux race verification is tracked separately in implementation status. No production-readiness or capacity claim is made.

Phase 07 execution is a restricted authenticated private demo on the explicit designated Docker environment. Base Compose leaves Run/Output unavailable, and execution-enabled production mode is rejected. One runner agent is supported; no scaling, public hostile-code boundary, package installation or interactive shell. Docker shares a host kernel and the agent alone has host-runtime authority; dedicated execution hosts plus gVisor/microVM isolation require a separate public release gate. Bounded local Python/JavaScript/resource/crash tests do not establish sustained fairness, daemon outages, host loss or backup readiness. Inputs/artifacts/output events remain retained without pruning. Expired/uncertain attempts fail rather than re-execute; a new explicit Run key is required. Exit 124 is reserved for timed_out, including a program choosing that exit code. The browser Run view currently belongs to the open workspace; authorized API events can be resumed using job ID and after/Last-Event-ID. Live OAuth and all earlier retention/outage/capacity/backup limitations remain.

Phase 08 search is eventual PostgreSQL literal substring matching over committed
Yjs cuts, with indexed/current sequences, current paths, 128-byte queries,
240-character snippets and at most 50 results. Filename matching works before
content is indexed. Refresh checks newer content; opening a match opens the current
file. No regex language, path matching, relevance ranking, pagination or freshness
SLA. Deleted/replaced generations and lost membership are filtered at query time.
NUL-bearing cuts retain exact UTF-8 bytes for snippets while matching uses an
unqueryable control separator. Projections/task rows are retained, and corrupt
histories cannot be indexed without operator repair. Claim expiry/takeover is
covered; actual search-worker death and sustained indexing fairness/latency are
unmeasured. Session/invite expiry across real project-lock waits is tested.
The review does not establish a public execution or production release boundary.
