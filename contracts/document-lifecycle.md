# Document and project lifecycle (frozen for Phase 00)

PostgreSQL is authoritative for metadata, permission, generations, durable Yjs update log, jobs and events. Redis stores disposable TTL presence/notification hints. Search text is a versioned projection. No `files.content` or other plain text store is authoritative. Each text file generation has one immutable document UUID, a `Y.Doc`, and one plain `Y.Text('content')`; file UUIDs survive rename/move. Delete tombstones files. Restore creates a new document UUID and increments generation; old updates are rejected and retained as separate recoverable drafts.

`documents.last_committed_sequence` starts at zero. A transaction locks the document row, verifies append policy and owner fence, inserts update identity/hash/bytes at next sequence and updates the counter. Encoded Yjs snapshots record a through sequence, state vector and checksum. Hydration applies a valid snapshot plus the contiguous retained tail; v1 keeps logs and enforces quota. The browser outbox is scoped by account/project/file/document generation, persists identity/hash/bytes before send, clears only matching durable ACK, and displays Saved only when no local item remains unacknowledged.

Phase 04 implements the server append/receipt/snapshot/fence path in `persistence.md`. `documents.snapshot_id` references a snapshot of the same document; publication cannot move it backward. Go initializes that pointer atomically with file creation. The browser currently tracks pending identities in memory only; the IndexedDB/outbox/draft portions of this contract remain Phase 05 requirements.

Tree operations use transactional `If-Match` tree versions, active sibling uniqueness including root, project/kind/parent/cycle/depth/path validation, bounded subtree tombstones and durable monotonically sequenced project events. Active project cap: 200 files and 10 MiB source; path ≤1024 UTF-8 bytes and folder depth ≤16.

Phase 02 uses a stricter 200-active-entry cap (files plus folders) to bound full-tree validation and subtree deletion. The Go API serializes metadata mutations by locking the project row, then rechecks the active session and editor role before applying the decimal `If-Match` version. A stale version returns 409 with `current_version`. Rename and move preserve file and document UUIDs. A file create calls the private TypeScript initializer, which constructs an empty `Y.Doc` with `Y.Text('content')`; Go atomically inserts the file, generation-one document, and through-sequence-zero encoded snapshot/checksum in the same PostgreSQL transaction. A failed initializer leaves no metadata. This is an empty authoritative Yjs state, not an editable or durable realtime room. Tree mutations insert both a sequenced `project_events` row and a `project.tree` outbox row in the same transaction. Deleted nodes retain historical rows/documents but disappear from active tree reads.

Named checkpoint states are `captured → materializing → ready | failed`. Capture the tree and each active document's committed cut in one repeatable read transaction, then materialize immutable, checksum verified artifacts. Only ready checkpoints are previewable/restorable/runnable. Owner restore first preserves prior state as a checkpoint, prepares new Yjs documents, then atomically switches tree/document pointers and emits events. Failed preparation leaves current state intact.

Run job states are `capturing → queued → running → succeeded | failed | timed_out | cancelled`; terminal states never transition again. A run waits for the requesting browser's durable receipts, captures a ready immutable checkpoint, and uses a fixed Python/JavaScript runtime template. Runner receives no application secrets, source mount is read only, network disabled, process nonroot, root filesystem read only, capabilities dropped, no-new-privileges and seccomp enabled. Initial quotas: 1 CPU, 128 MiB RAM, 32 PIDs, 5 second wall time, 16 KiB stdin, 64 KiB combined output, one active run/user. This is a private demo boundary requiring stronger isolation before public hostile execution.
